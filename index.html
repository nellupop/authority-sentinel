Architecture

How a single check actually runs

This part genuinely is a sequence — each step hands off to the next one, in order, every five minutes.

1

A scheduled cron job wakes a real agent turn

Not a headless dispatch — a declarative job_type = "agent" cron job that gives the SOP engine a live agent loop to run against.

2

The agent calls the stock shell tool

One fixed, literal command — no free-form input, so there's nothing for a prompt injection to land in.

3

A stdlib-only Python script hits live Solana RPC

Parses the BPF-Loader-Upgradeable and SPL Token Mint account layouts by hand, byte offsets and all — no SDK dependency.

4

State gets diffed and written to disk

First run just establishes a baseline. No prior state means no false-positive alert.

5

Telegram gets a message — only if something changed

Zero changes, zero noise. That silence is the point.

Safety & custody

What it can and can't do

Custody tier T0 — read-only

WHAT IT HOLDS

  • An optional Solana RPC key
  • A Telegram bot token
  • Nothing else

WHAT IT CAN NEVER DO

  • Hold a wallet
  • Sign a transaction
  • Move any funds, anywhere
